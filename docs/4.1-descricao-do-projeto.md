# 4.1 Descrição do Projeto

## O problema, na voz do cliente

<!-- Uma a três frases, do jeito que o cliente falou, entre aspas. Depois das aspas, o papel dele entre parênteses. -->

> _"Minha principal preocupação é a falta de visibilidade em tempo real sobre o estado real de cada dragão. Sem um controle rígido do treinamento e dos cuidados diarios, corro risco de solicitar uma criatura para uma missão de alta importancia e descobrir tarde demas que ela não estava alimentada adequadamente ou preparada para aquele desafio."_ (Lucerys, dono de dragão, que solicita seus dragões pra missões especificas.)

## Propósito

<!-- Conte como o problema acontece hoje e que sistema é este. Duas ou três frases bastam.
     Tela, botão, cor e aplicativo não entram aqui. Isso é solução, e a solução vem depois. -->

_Atualmente, o controle d alimentação, cuidados, treinamentos e a escala de missões dos dragãos sao feitos de forma descentralizada e manual, o que gera falhas graves de comunicação e falta de rastreabilidade sobre a real situação de cada dragão. O Dracarys é um sistema de informação de gestao intregada que centraliza todoo historico de saude, evolução de treino e disponibilidade. Ele serve para organizar e garantir que nenhuma decisão estrategica seja tomada com base em informaçoes nao atualizadas._

## Objetivo

<!-- O que vai ser verdade quando o sistema estiver funcionando. Escreva de um jeito que o cliente consiga conferir.
     "Melhorar a organização" ninguém confere. "Nenhuma encomenda entregue no dia errado" o cliente confere na primeira semana. -->

_Garantir que nenhum dragão seja designado para missão se estiver com o treinamento incompleto, com fome ou machucado, permitindo que o cliente veja a situação real de prontidão de qualquer dragão antes de autorizar a partida para as missões._

## Quem usa

<!-- Escreva papéis, não pessoas. Para cada perfil, diga o que ele faz no sistema.
     Se quem pediu o sistema não usa nenhum dos perfis, conte isso numa frase à parte. -->

- **Administrador.** _Cadastra os dragões no sistema, cuida das configurações gerais e puxa relatorios para ver como o ninho está evoluindo._
- **Treinador.** _Alimenta o sistema todo dia marcando o que os dragões comeram, os cuidados de saude que receberam e como foi o desempenho deles no treino._
- **Cliente.** _Pode consultar o catalogo de dragões ativos, verifica os status do seu propio dragão ou de outros e envia pedido para o uso das criaturas._

## Escopo

<!-- O que o sistema faz. De 4 a 6 itens, cada um com um verbo. -->

- O sistema cadastra os perfis de cada dragão com foto, tamanho, nome, idade, mania e restrições.._
- O sistema registra o que os dragões comeram, as consultas como veterinario e os remedios e cuidados que tiveram._
- O sistema acompanha a evolução dos treinos e quais habilidades o dragão ja domina._
- O sistema checa se o dragão está realmente alimentado, saudavel e treinado antes de deixar ele ir a uma missão._
- O sistema avisa a equipe com alertasse algum dragão estiver há muito tempo sem comer ou com o trein atrasado._

## Fora do escopo

<!-- Pelo menos 2 itens, cada um com o porquê. Item sem porquê parece esquecimento. Com o porquê, vira decisão. -->

- _O sistema não vai rastrear o dragão pelo mapa (GPS) enquanto ele voa, porque a ideia agora é organizar o ninho antes deles decolarem, e não monitorar o voo no céu._
- _O sistema nao vai cobrar moedas pelas missões, porque o dinhero e os pagamentos combinados com o cliente são resolvidos por fora de forma direta._

## Características principais

<!-- Onde o sistema funciona, quem pode mexer em quê e o que precisa ser rápido ou seguro.
     Dê número sempre que der, como "em menos de três segundos".
     Escopo é o que o sistema faz. Característica é como ele faz. Não repita o escopo aqui. -->

_O sistema operará como uma aplicação web responsiva, acessível via navegadores de desktops e dispositivos móveis, com autenticação obrigatória via login e senha criptografados para garantir que apenas perfis autorizados visualizem os dados táticos. O software processará e atualizará as mudanças de status das criaturas e a validação de missões em menos de 2 segundos. Para assegurar a integridade das operações, todas as ações de alteração de dados de saúde e prontidão gerarão logs de auditoria imutáveis._
